How to use herdrboard

herdrboard is a kanban board that hands each card to a coding agent running in herdr. Every agent is a normal, interactive Claude Code session, so you can watch it in Ovis and type to it whenever you want. The board decides what each agent works on and tracks where every card is.

browser · phone"]) -->|web UI| board["herdrboard

split pane"]
  orch & w & r -->|hb CLI| board
  ovis(["Ovis / herdr TUI"]) -.->|same panes| herdr
The board never runs agents itself. It asks herdr to open panes, then types a profile command such as cc2 into them.

Quick start

  1. Install and start the service. This puts hb on your PATH and keeps the board running with launchd. 
    git clone https://github.com/dzakybd/herdrboard && cd herdrboard
./scripts/install.sh
  2. Open the board at http://127.0.0.1:7420. On your phone, run hb url and open that link once (see Phone access).
  3. Add a project. Open folder_open Projects, press Browse, click through to your repository (git repos are marked), then Add project. A folder of several repositories works too: workers pick the repositories and make their own worktrees under .hb-worktrees/<card>/, which Finish leaves in place.
  4. Check the agents. In settings Settings, pick the profile, model, effort and mode for the orchestrator, worker and reviewer. Your cc1…cc4, ccd functions are already listed.
  5. Create a card with New card. Write the brief as if for a new teammate: the worker sees only the brief. Leave it in Todo and a worker starts within a few seconds.
  6. Watch it on the board, or press Open in herdr on the card to jump to the live session in Ovis.

Board and lanes

Cards move left to right. You move cards between Backlog and Todo, and to Done. The board moves everything else, based on what the agents report and what herdr sees.

stateDiagram-v2
  direction LR
  [*] --> Backlog
  Backlog --> Todo: you start it
  Todo --> Working: worker launched
  Working --> Review: hb done (review on)
  Working --> Ready: hb done (review off)
  Review --> Working: changes requested
  Review --> Ready: approved
  Working --> NeedsYou: blocked · hb ask · stopped · exited
  Review --> NeedsYou: blocked · stopped
  NeedsYou --> Working: agent works again
  Ready --> Done: Finish
  Done --> [*]
LaneMeaning
BacklogParked. Nothing runs.
TodoQueued. Starts as soon as fewer than Max parallel workers (default 3) are busy.
WorkingA worker is on it, in its own git worktree and branch hb/<id>-<slug>.
ReviewA reviewer agent is checking the diff in a pane next to the worker.
Needs youAn agent is waiting on you. The card says why.
ReadyDone and (if review was on) approved. The branch has the commits.
DoneFinished: the worktree is removed, the branch is kept. Hidden after 3 days.
info

Finish (or dragging to Done) removes the card's worktree and closes its herdr workspace. herdr refuses if there is uncommitted work. Merging the branch or opening a PR is up to you, or put "open a PR" in the brief.

A card's life

Here is what happens behind one card with review on:

sequenceDiagram
  autonumber
  participant B as herdrboard
  participant H as herdr
  participant W as Worker (cc2)
  participant R as Reviewer (ccd)
  B->>H: worktree create hb/12-add-login
  B->>H: pane run "HB_CARD=12 cc2 --model … --permission-mode …"
  H-->>B: agent idle (answers folder-trust prompt if shown)
  B->>W: "Read ~/.herdrboard/cards/12/worker.md and follow it."
  W->>W: works, commits on its branch
  W->>B: hb done --summary "…"
  B->>H: split pane, start reviewer
  B->>R: "Read reviewer.md and follow it."
  R->>B: hb review --changes "1. …"
  B->>H: close reviewer pane
  B->>W: reviewer feedback (round 1 of 2)
  W->>B: hb done
  B->>R: fresh reviewer
  R->>B: hb review --approve
  B->>B: card → Ready
Each round gets a fresh reviewer. After Max review rounds (default 2) of changes, the card goes to Needs you.

Turn Agent review off on a card (or as a project default) when you want speed: hb done then sends the card straight to Ready. A card with Own worktree off runs in a tab in the project's main checkout instead, which suits read-only jobs like a PR-review sweep.

Agents and profiles

There are three roles: orchestrator, worker and reviewer. Each role has four settings:

SettingBecomesExample
Profilethe command typed into the panecc2 (your zsh function)
Model--modelopus, sonnet, glm-5-3-flash-2
Effort--effortlow · medium · high · xhigh · max
Mode--permission-modebypassPermissions (default), acceptEdits, auto, plan…

Settings are layered, and each field falls back on its own. A card can change only the effort and still use the project's model:

flowchart LR
  c["Card override
(worker, reviewer)"] -->|empty field| p["Project override
(all three roles)"] -->|empty field| s["Settings default"]
  c & p & s --> cmd["cc2 --model opus --effort high
--permission-mode bypassPermissions"]
warning

Any mode other than Bypass makes the agent stop at permission prompts, including before it runs hb done. Those cards wait in Needs you until you approve in herdr.

To use a tool other than your cc functions, add a profile in Settings with any command, such as claude or codex. Model, effort and mode flags are Claude Code flags, so leave them empty for other tools.

Orchestrator

Pick a project in the top bar and the orchestrator strip appears. Press Start: herdrboard opens a tab in the project's main checkout and starts the orchestrator profile there. Then tell it what you want, either in the strip on the board or in its terminal in Ovis. It breaks your request into self-contained cards with hb card add, and workers pick them up.

You:  Add rate limiting to the public API and document it.
Orch: hb card add "Rate-limit public API" --brief "…" --model opus --effort high
      hb card add "Document rate limits" --brief "…" --no-review

The orchestrator only files and tracks cards. It does not write code itself.

Automations

An automation creates a card on a schedule. Open schedule Automations and give it a title, a schedule, a brief, and optionally its own agent settings. The title becomes the card title. Use edit to change an automation later. A changed schedule counts from that moment.

ScheduleCLI triggerFires
Every daydaily 09:00every day at 09:00 local time
Every weekdayweekdays 09:00Monday to Friday at 09:00
Every weekweekly mon 09:00every Monday at 09:00
On an intervalevery 30m · every 2h · every 1dat that interval

If the Mac was asleep at the scheduled time, it fires once on wake. An automation has one card at a time. If its previous card is in Ready, the next fire finishes it for you (the worktree is removed, the branch is kept), so read the result before then. If that card is still in progress, or can't be finished because of uncommitted work, the fire is skipped, never queued, and the reason is in the card's activity. Run fires it now.

Needs you

The board watches each agent's state in herdr. A card turns red in Needs you when:

Reason on the cardWhat to do
Waiting for a permission or an answer in herdrPress Open in herdr and answer the prompt. The card returns on its own.
A question the agent asked with hb askType the answer in Reply to the agent on the card, or in its terminal.
Stopped without running hb doneReply with what's missing, or tell it to run hb done.
Review still failing after 2 roundsRead the notes, then reply to the worker or finish the card yourself.
The agent exited / launch failedFinish the card, then create it again.

Phone access

The board listens on all interfaces (port 7420). Because agents can run with bypassed permissions, every device other than the Mac needs a token.

  1. On the Mac, run hb url. It prints something like http://your-mac.local:7420/?token=…
  2. Open that link on your phone once. It stores a cookie and drops the token from the address bar.
  3. From then on, http://your-mac.local:7420 just works on that phone. Add it to your home screen.
lock

It is plain HTTP: use it only on a network you trust, or reach it through Tailscale. To revoke every device, delete ~/.herdrboard/token and run launchctl kickstart -k gui/$(id -u)/dev.dzaky.herdrboard.

CLI reference

Everything in the UI is also in hb. Agents use the same commands, and $HB_CARD / $HB_PROJECT fill in the ids for them.

CommandDoes
hb project add <path>Register a repository or a folder of repositories
hb card add "<title>" --brief "…"Create a card in Todo. Add --backlog, --no-review, --no-worktree, --worker cc2, --model, --effort, --mode
hb card list [--lane needs_you]List open cards
hb card show <id>Brief, summary, branch and activity log
hb card move <id> todo|backlog|doneStart, park or finish a card
hb done --summary "…"Worker: the task is finished
hb review --approve / --changes "…"Reviewer: the verdict
hb ask "…"Any agent: ask you a question
hb orch start / hb orch say "…"Start or message the orchestrator
hb automation add|list|runManage automations
hb export [file]Save projects, automations, card history and settings as JSON (also in Settings)
hb import <file> [--dry-run] [--path P=PATH] [--skip P]Check an export against this machine, then import it, all or nothing (also in Settings)
hb urlLink for your phone
hb serveRun the board in the foreground (launchd normally does this)

Agent skill

To teach any coding agent (in any session, not only ones the board started) how to use the board, install the skill:

npx skills add dzakybd/herdrboard

Then you can say "put this on the board" or "what's waiting for me on herdrboard?" in any Claude Code session.

Troubleshooting

A card is stuck in Working

Press Open in herdr and look at the agent. If it finished but forgot to report, tell it to run hb done. The board flags this on its own once the agent goes idle.

"herdrboard is not running"

launchctl kickstart -k gui/$(id -u)/dev.dzaky.herdrboard
tail -f ~/.herdrboard/serve.log

Finish fails

herdr won't remove a worktree with uncommitted changes. Open it in herdr, commit or discard, then Finish again.
